# TileLang feasibility study (paper §4.4 / §5.6)

Hand-written [TileLang](https://github.com/tile-ai/tilelang) kernels used for
the quantified feasibility study of TileLang as an optional code-generation
target. These are **hand-written** reference kernels (not generated by Ionia);
they measure TileLang's ceiling and its FP32-semantics hazard.

The raw measurement logs are in `../../../logs/` (`tl_*.log`,
`triton_same_shape_bench.log`); the numbers below are copied from them.

## Environment

- GPU: NVIDIA RTX PRO 4000 Blackwell Laptop (60 SMs, sm_120), driver 596.58
- TileLang 0.1.13, PyTorch 2.13.0+cu130, cuDNN 9.2
- The system has no CUDA toolkit installed; TileLang's JIT needs one, so a
  CUDA 13.3 toolchain was assembled from pip wheels (`nvidia-cuda-nvcc`
  13.3.73 + `nvidia-nvvm` + `nvidia-cuda-cccl` + `nvidia-cuda-runtime`),
  pointed to via `CUDA_HOME` (the scripts default it to
  `~/torch_env/lib/python3.12/site-packages/nvidia/cu13`; override the
  `CUDA_HOME` environment variable for your own install). All nvcc/cicc/ptxas
  /CCCL/runtime components must share the same minor version — this version
  alignment is the toolchain fragility the paper refers to.

## Scripts and measured results

- `tl_smoke_vecadd.py` — minimal vector-add smoke test (verifies the
  pip-assembled toolchain JIT-compiles for sm_120a; max err 0.0).
- `tl_gemm_bench.py` — two GEMM-class benchmarks
  (log: `logs/tl_gemm_bench.log`):
  - GEMV, VGG16 fc1 shape (M=1, K=25088, N=4096, memory-bound): best
    TileLang config 863.4 µs (476 GB/s, ~91% of DRAM peak) vs. cuBLAS FP32
    564.9 µs (728 GB/s).
  - GEMM 4096³ via `T.gemm` (tensor-core path): best config
    (BM128/BN128/BK32, 256 threads, 2 stages) **2.854 ms = 48.15 TFLOP/s**,
    vs. `torch.matmul` (cuBLAS) TF32 3.044 ms = **45.15 TFLOP/s** and
    strict-FP32 `torch.matmul` 8.843 ms = 15.54 TFLOP/s. The numeric check
    against an FP64 reference shows max abs err 2.69e-3, **rel err
    7.62e-4** — the signature of `T.gemm` *silently* lowering FP32 inputs to
    TF32 tensor cores (paper: rel. err. 7.6e-4; unlike Triton's
    `input_precision="ieee"`, TileLang exposes no strict-FP32 switch).
- `tl_conv_bench.py` — direct-tiled (explicit loops) FP32 conv2d, ResNet-18
  stage-2 shape 128→128 @ 28×28, k3 s1 p1, batch 1 (231.2 MFLOP)
  (log: `logs/tl_conv_bench.log`; sweep data: `conv_results.json`):
  best config 198.3 µs min / 200.4 µs med (1.17 TFLOP/s), max err 6.25e-5
  (true FP32 arithmetic). Same-session cuDNN: strict FP32 213.4/252.4 µs,
  TF32 44.0/51.8 µs. In strict FP32 this is the slowest of the four
  implementations measured (generated CUDA, Triton, cuDNN, TileLang — see the
  Triton line below).
- `tl_conv_gemm_bench.py` — same conv shape as an *implicit GEMM* (in-kernel
  im2col gather + `T.gemm`) (log: `logs/tl_conv_gemm_bench.log`):
  best config 30.3 µs min / 34.1 µs med (7.64 TFLOP/s), i.e. **matches/beats
  cuDNN TF32 (44.0 µs min) on this ResNet-18 shape** — but max err 5.98e-3
  again shows the result is silently TF32, not FP32.
- `tl_lenet5.py` — full hand-written TileLang LeNet-5 chain (10 kernels),
  checked against the NumPy reference of `../validate_lenet5.py` on identical
  data (log: `logs/tl_lenet5.log`): all kernels pass, max abs err
  **1.49e-8**; end-to-end chain 91.6 µs min / 131.2 µs median (second run:
  102.1 µs min — reproduced).
- `triton_same_shape_bench.py` — same-shape Triton controls
  (log: `logs/triton_same_shape_bench.log`): conv 128→128 @ 28² strict FP32
  122.2 µs (1.89 TFLOP/s); GEMV 25088×4096 7712 µs; matmul 4096³
  `input_precision="ieee"` 14.58 TFLOP/s (err 0.0) vs. TF32 32.75 TFLOP/s
  (err 2.59e-3) — the explicit precision switch TileLang lacks.

## Paper claims backed by these files

| Paper claim (§4.4 / §5.6) | Evidence |
|---|---|
| TileLang GEMM 48.15 TFLOP/s on 4096³, beats cuBLAS TF32 45.15 | `tl_gemm_bench.py`, `logs/tl_gemm_bench.log` |
| `T.gemm` implicit-GEMM conv matches cuDNN TF32 on ResNet-18 shapes | `tl_conv_gemm_bench.py`, `logs/tl_conv_gemm_bench.log` (30.3 vs. 44.0 µs) |
| Silent TF32 lowering, rel. err. 7.6e-4, no FP32 switch | `logs/tl_gemm_bench.log` (rel 7.62e-4), `logs/triton_same_shape_bench.log` (Triton `ieee` control) |
| Direct-tiled conv slowest of four in strict FP32 | `logs/tl_conv_bench.log` (198.3 µs) vs. `logs/triton_same_shape_bench.log` (122.2 µs) and cuDNN FP32 in the same logs |
| Toolchain fragility (pip-assembled nvcc, version alignment) | `CUDA_HOME` setdefault in each script; see Environment above |
